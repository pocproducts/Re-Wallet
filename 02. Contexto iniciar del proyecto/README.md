# Contexto

Borradores del diseño, de la etapa en que el proyecto todavía no sabía qué
era. Se conservan porque muestran cómo se llegó a la arquitectura actual, y
porque las decisiones que nacieron acá todavía se discuten.

## Qué hay acá

Quince diagramas `.mermaid` de la etapa de exploración: flujos de sesión,
modelos de cartera, y las alternativas que se descartaron.

## Qué **no** hay acá

El schema de Postgres y el seed inicial. Son código ejecutable, no contexto:
están en [`../07.PockBackend/sql/`](../07.PockBackend/sql/), que es donde un backend los
busca.

## Por qué no se borran

Un repo del que se borró el camino no muestra por qué se eligió lo que se
eligió. Estos diagramas son eso. Si alguno dejara de corresponder a la
arquitectura actual, lo correcto es marcarlo, no borrarlo.
